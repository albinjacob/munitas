Munitas · Finance organisation · Governed datasets

Making a new dataset from a query, without loosening any rule

Munitas is a governance platform: it decides who may read which piece of data, and it keeps a permanent record of every decision. This walkthrough follows an analyst in a finance organisation who is stopped at a restricted table of card transactions, asks for access, and is answered by the custodian of the department that owns it. That person then makes a new dataset from a query. The platform runs the query itself, checks the result, and keeps the new dataset exactly as restricted as the data it came from. When the custodian withdraws the access, the new dataset closes too. Every name in the example data is invented.

How to read this page

  • Every step names the tool or the part of Munitas where it happens.
  • Console steps happen in the Munitas console, the web app that people open in a browser. They show real screenshots.
  • Python steps happen in Python, on the person’s own computer, in a notebook or in a terminal. Python is a window where a person types a line and sees the answer straight away. From there the person uses the Munitas client library, which sends requests to Munitas, and DuckDB, a free tool for analysing tables. Each dark box on the page is one of these steps.
  • In a dark box, the top part is exactly what was typed and the bottom part is exactly what came back. me is the client library signed in as the person named on the label, and custodian is the client library signed in as the custodian.
  • Every step was run for real by a script that types each one, so the answers are genuine and nothing has been edited.

The parts of Munitas, and the tools around it

Console
The Munitas web app that people open in a browser. It calls the control plane for everything it shows.
Control plane
Munitas’s API service. It decides who may do what, keeps the permanent record of every decision, and starts the work for new datasets.
Catalog
The part of the control plane that lists tables for tools such as DuckDB and hands them a short-lived key to read the files.
Storage
SeaweedFS, the object storage where the files of every dataset are kept.
Sandbox worker
A background worker that runs the query for a new dataset in an isolated container named munitas-derive-runner, which has no network connection and no passwords.
Munitas client library
A small Python library, munitas_client.py, that a person uses in Python to send requests to the control plane.
DuckDB
A free tool for analysing tables. It runs on the person’s computer and reads tables from Munitas through the catalog.

Words used on this page

Organisation
A company or hospital group that uses Munitas. Each organisation sees only its own data.
Department
A team inside an organisation that owns some of its data, such as Cardiology.
Dataset
A named collection of records, such as a table of patient admissions.
Custodian
The person a department trusts to decide who may read its data.
Access level
How restricted a dataset is. Raw is the most restricted, and nobody may read it without permission. Published is the most open.
Lease
Permission, given by the custodian, to read one dataset for one stated purpose and for a limited time.
Query
A question about a dataset, written in a language called SQL.
Sensitivity label
How identifying a column is. none does not identify anybody, quasi is a detail that could help identify a person when combined with others, and phi is protected health information.
Token
A short-lived password that also states why the person wants to read.
Sealed
Finished and closed for good, so that it can never be edited.
Iceberg table
An open way of storing a table that tools such as DuckDB can read directly.

PART ONE

A closed table, and a request for access

The Fraud Operations department of a finance organisation owns a dataset of card transactions. Every record names the account holder and the last four digits of the card, so the dataset is closed to most people. An analyst wants to review it. This part shows the analyst being stopped, asking for access, and being answered by a different person.

PART TWO

Making a new dataset from a query

Omar only needs the large payments made outside the home country. Munitas lets a person make a new dataset by writing a query over datasets the person may already read. The platform runs the query itself, not the person's computer, and holds the new dataset to the same rules as the data it came from.

9
Omar
The platform shows its plan before anything runs
Python on Omar’s own computer, using the Munitas client library

Omar writes a query that joins the restricted transactions with the public list of merchants and keeps payments over 300 made outside the United States, then asks the platform to plan it. Nothing runs yet. The platform replies with the columns the new dataset would have, and the sensitivity label each one must carry: none for a column that does not identify anybody, and quasi for a detail that could help identify a person when combined with others.

Typed by Omar, in Python on Omar’s own computerme is the Munitas client library, signed in as Omar. Its commands call the control plane, which is Munitas’s API and the part that decides who may do what.
sql = """SELECT t.txn_id, t.amount, t.country, t.occurred_at, m.category, m.high_risk, t.flagged
FROM t JOIN m ON m.merchant_id = t.merchant_id
WHERE t.amount > 300 AND t.country <> 'US'"""
draft = me.draft(inputs=[{"dataset": "transactions", "alias": "t"}, {"dataset": "merchants", "alias": "m"}], sql=sql, name="large-foreign-transfers-over-300",
                 primary_key=["txn_id"], purpose="cross-border fraud review")
for f in draft["fields"]:
    print(f"{f['name']:<22}{f['type']:<8}{f['sensitivity']}")
print("The new dataset would be class", draft["output_class"])
What came back
txn_id                string  none
amount                float   none
country               string  quasi
occurred_at           string  quasi
category              string  none
high_risk             bool    none
flagged               bool    quasi
The new dataset would be class RAW
category and high_risk, which come from the public list of merchants, are none. country, occurred_at and flagged, which come from the transactions, are quasi. The last line says the new dataset would be RAW, because it takes the strictest level among its inputs.

A label can be raised but not lowered. Lowering one would claim that the data is safer than the data it came from, and that claim needs somebody other than the person who wrote the query. Omar tries to mark the country column as none anyway.

Typed by Omar, in Python on Omar’s own computerme is the Munitas client library, signed in as Omar. probe = me.draft(inputs=[{"dataset": "transactions", "alias": "t"}], sql="SELECT txn_id, country FROM t", name="large-foreign-transfers-over-300-probe",
                 primary_key=["txn_id"], purpose="cross-border fraud review")

except MunitasError as exc:

What came back
Refused: HTTP 422: 'country' is computed from fields marked 'quasi', so it cannot be marked 'none'. A sensitivity can only be raised here: lowering one needs the agreement of somebody other than the person who wrote the query
The platform refuses and explains: country is computed from a field marked quasi, so it cannot be marked none.

PART THREE

The rules hold
