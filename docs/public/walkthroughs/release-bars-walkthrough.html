Set the bars a result is released under

The data protection officer writes down how much identifying detail a de-identified result may still hold, once for each audience it is released to. Each is a named bar with a figure for all kinds of identifier together and a limit for each kind. Everyone in the organisation can read the bars, and only the data protection officer can set one.

Words used on this page

Organisation
A company or hospital group that uses Munitas. Each organisation sees only its own data.
Data protection officer
A person who watches how an organisation handles personal data. The role decides nothing about who may read it.
De-identification reviewer
A role that allows a person to review data from which identifying details have been removed, and to decide whether it may be released.
Release bar
A set of limits an organisation chooses for how much identifying detail a result may still hold, kept under a name for the audience the result is released to. A change adds a new version and the earlier ones stay.
Version
One sealed state of a dataset. Changing the contents means making a new version, never editing an old one.
Release
A decision to let a dataset version be read more widely than before. A release changes who may read it and moves no data.

PART ONE

The data protection officer writes down the bars

A de-identified result is released to a particular audience, and how much identifying detail it may still hold depends on who that audience is. A release bar is a named set of limits an organisation writes for one audience. An identifier is a detail that points to a person, such as a name or a phone number.

1
Nakamura
Nakamura opens the Release bars page, and the organisation has no bar of its own yet
Munitas console · Release bars · /release-bars

Nakamura is the data protection officer of the Health organisation, a person who watches how the organisation handles personal data. Until the organisation writes a bar, every result is judged by the one the platform starts with, called Platform default: at least 98 percent of identifying detail removed overall, and none of the kinds that name a person directly left in the clear. The platform says plainly that this is a starting point to argue with, not a standard.

The page says This organisation has not set a release bar yet, so every result is judged by the Platform default bar below. Under Platform default, Identifying detail removed, over all kinds together: 98%, and each of the five kinds that name a person directly reads None allowed under Left in the clear, at most.
2
Nakamura
Nakamura writes the first bar, for the annotation team
Munitas console · Release bars · Create a release bar

A bar has a name, one figure for all kinds of identifier together, and, for each kind, the least that must be removed and the most that may be left in the clear. The form starts from the Platform default, so a new bar never quietly drops a limit the platform starts with. The result Imani will decide is going to the annotation team, the people who label data inside the organisation. Nakamura names the bar for them, lowers the overall figure to 95 percent, and asks for at least 90 percent of addresses and places to be removed. Names, phone numbers and the other kinds that name a person directly keep their limit of none.

The name reads Annotation team and the overall figure reads 95. Under Kinds that name a person directly every row has 0 in the last column, and An address or a place has 90 under Removed, at least (percent). The reason reads The annotation team works inside the organisation and may keep a few addresses or places in a result, but never a name, a phone number or a record number.
3
Nakamura
The bar is saved as version 1, with who made it and when
Munitas console · Release bars · /release-bars

A bar is never edited. A change adds a version, and the earlier versions stay, so that a decision made later can say exactly which version of which bar it was judged by. The saved bar shows its limits in a table, with No limit where Nakamura set none.

The card reads Annotation team and Version 1 by Nakamura, followed by the date and time. Reason: shows Nakamura's reason. The last row, An address or a place, reads 90% under Removed, at least, and a button reads Change.
4
Nakamura
Nakamura adds a stricter bar for results that leave the organisation
Munitas console · Release bars · /release-bars

The Public release bar asks for 99 percent overall and for at least 99 percent of dates of birth and of addresses and places. An organisation keeps as many bars as it has audiences, and the person who releases a result chooses between them.

The list now holds Annotation team and Public release, each marked Version 1 by Nakamura. Under Public release, Identifying detail removed, over all kinds together: 99%, and A date of birth and An address or a place both read 99%.
PART TWO

The reviewer reads the bars and cannot change them

A de-identification reviewer is a person who holds the role that decides whether a result with the names removed may be released.

5
Imani
Imani can read the bars, and cannot set one
Munitas console · Release bars · /release-bars

Everybody signed in can read the organisation's bars, so that a reviewer can choose one and anybody can see what a result was held to. Only the data protection officer sets them, so that the person who decides a release cannot loosen the bar it is judged by.

Both bars are listed, and there is no button to create or change one. At the foot of the list the page says Only the data protection officer may set a release bar.
