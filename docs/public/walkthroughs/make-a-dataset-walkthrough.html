Make a new dataset from a query, under the same rules

A researcher who holds a lease makes a new dataset from a query. Munitas runs the query itself, checks the result, and keeps the new dataset exactly as restricted as the data it came from. A colleague without access is refused, a query that reaches too far is stopped, and when the custodian withdraws the access the new dataset closes too.

How to read this page

  • Every step names the tool or the part of Munitas where it happens. The label under the title says where, and the step reads in the same order each time: what is happening, the evidence, and then what to look for in it.
  • Console steps happen in the Munitas console, the web app that people open in a browser. They show real screenshots, and clicking one enlarges it.
  • Python steps happen in Python, on the person’s own computer, in a notebook or in a terminal. Python is a window where a person types a line and sees the answer straight away. From there the person uses the Munitas client library, which sends requests to Munitas, and DuckDB, a free tool for analysing tables. Each dark box on the page is one of these steps.
  • In a dark box, the top part is exactly what was typed and the bottom part is exactly what came back. me is the client library signed in as the person named on the label, and custodian is the client library signed in as the custodian.
  • Every step was run for real by a script that types each one, so the answers are genuine and nothing has been edited. Every name of a person, patient or card holder in the example data is invented.

Words used on this page

Organisation
A company or hospital group that uses Munitas. Each organisation sees only its own data.
Department
A team inside an organisation that owns some of its data, such as Cardiology.
Dataset
A named collection of records, such as a table of patient admissions.
Custodian
A person who holds the data custodian role, which allows deciding who may read data. A custodian decides for the departments they are an approver for.
Access level
How restricted a dataset is. Raw is the most restricted, and nobody may read it without permission. Published is the most open.
Lease
Permission, given by the custodian, to read one dataset for one stated purpose and for a limited time.
Query
A question about a dataset, written in a language called SQL.
Sensitivity label
How identifying a column is. none does not identify anybody, quasi is a detail that could help identify a person when combined with others, and phi is protected health information.
Token
A short-lived password that also states why the person wants to read.
Sealed
Finished and closed for good, so that it can never be edited.
Iceberg table
An open way of storing a table that tools such as DuckDB can read directly.
Version
One sealed state of a dataset. Changing the contents means making a new version, never editing an old one.
Container
An isolated environment, with no network access of its own, where Munitas runs an agent.

PART ONE

Making a new dataset from a query

Sam, a researcher, only needs the older patients with a long-term heart condition. Munitas lets a person make a new dataset by writing a query, which is a question about tables written in a language called SQL, over datasets the person may already read. Munitas runs the query itself, not the person's computer, and holds the new dataset to the same rules as the data it came from. Sam holds a lease, which is permission from the custodian to read one dataset for a stated purpose and a limited time, and it is still in force.

1
Sam
Munitas shows its plan before anything runs
Python on Sam’s own computer, using the Munitas client library

Sam writes a query that joins the restricted admissions with the public diagnosis lookup and keeps patients over 65 with a chronic condition, then asks Munitas to plan it. Nothing runs yet. Munitas replies with the columns the new dataset would have, and the sensitivity label each one carries: none for a column that does not identify anybody on its own, quasi for a detail that could help identify a person when combined with others, and phi for protected health information, which means facts about a person's health.

Typed by Sam, in Python on Sam’s own computerme is the Munitas client library, a small Python package that asks Munitas for things on the person’s behalf, signed in as Sam.
sql = """SELECT a.admission_id, a.age, a.diagnosis_code, d.description, d.chronic,
       a.length_of_stay_days, a.readmitted_30d
FROM a JOIN d ON d.code = a.diagnosis_code
WHERE a.age > 65 AND d.chronic"""
draft = me.draft(inputs=[{"dataset": "admissions", "alias": "a"}, {"dataset": "diagnosis_codes", "alias": "d"}], sql=sql, name="chronic-heart-patients-over-65-1011-1021",
                 primary_key=["admission_id"], purpose="readmission study")
for f in draft["fields"]:
    print(f"{f['name']:<22}{f['type']:<8}{f['sensitivity']}")
print("The new dataset would be class", draft["output_class"])

All seven columns are none, as the contract that Devi uploaded said for each of them. The last line says the new dataset would be RAW: a new dataset takes the strictest access level among its inputs, and the admissions are Raw.

After Sam confirms, Munitas copies the input files into a sandbox, an isolated container with no network connection and no passwords. The query runs there, and Munitas checks every row of the result against the plan. The query never runs on Sam's computer. Sam's session only waits for the answer.

To run the query, Munitas starts it in a sandbox, an isolated container with no network, and writes the result back as a new dataset.Names used here that are not defined in this box: draft was set in step 1.
confirmed = me.confirm(draft)
result = me.wait(confirmed["id"])
print("Status:", result["status"])
print("New dataset:", result["target_name"], "|", result["output_class"])
What came back
Status: succeeded

The status is succeeded, and the new dataset is RAW again. Sam did not choose that level: it follows from the datasets the query read.

PART TWO

The rules still apply to the new dataset

A new dataset is only safe if nobody can use it to get around the rules. This part tests that with a colleague, with a query that reaches too far, and with the custodian taking the access back.

7
Devi
A colleague without access is refused
Python on Devi’s own computer, using the Munitas client library and DuckDB

Devi is a data engineer in the same organisation, with no lease on the new dataset. The new dataset is as restricted as the data it came from, so Devi cannot open it.

Typed by Devi, in Python on Devi’s own computercolleague is the Munitas client library, a small Python package that asks Munitas for things on the person’s behalf, signed in as Devi. DuckDB runs in this Python session. It asks Munitas for the table. If Munitas allows it, DuckDB receives a short-lived key and reads the table directly.
colleague_token = colleague.catalog_token(purpose="curiosity")
other = colleague.attach_duckdb(colleague_token)
try:
    print(other.sql('SELECT count(*) FROM lake."chronic-heart-patients-over-65-1011-1021".v1'))
except Exception as exc:
    print("Refused:", exc)
What came back
Refused: HTTP Error: GetTableInformation endpoint returned response code Forbidden_403 with message "no role reaches class RAW"
The reason is the same as before: no role reaches class RAW. Working in the same organisation is not enough.

A query that reads outside its inputs is stopped
Python on Sam’s own computer, using the Munitas client library

A query may read the datasets it names and nothing else. Sam tries one that reads a file from the machine instead.

Typed by Sam, in Python on Sam’s own computerme is the Munitas client library, a small Python package that asks Munitas for things on the person’s behalf, signed in as Sam.Names used here that are not defined in this box: MunitasError is the error the client library raises when Munitas refuses a request.
try:
    me.draft(inputs=[{"dataset": "admissions", "alias": "a"}], sql="SELECT content AS admission_id FROM read_text('/etc/passwd')",
             name="chronic-heart-patients-over-65-1011-1021-escape", primary_key=["admission_id"], purpose="readmission study")
except MunitasError as exc:
    print("Refused:", exc)
What came back
Refused: HTTP 422: that query reaches outside the datasets it declared (a file or an address). A query may read only its declared inputs
Munitas refuses with that query reaches outside the datasets it declared. Nothing ran.

Every refusal is on record, with the reason
Munitas console · Access decisions · /audit

The decision log lists every request to read data. Each request is recorded twice: once for whether it was allowed, and once for whether access was actually given. Here the log is filtered to the requests that were refused.

Every row says no. The two newest are Devi's attempt, with the stated purpose curiosity, and Sam's first attempt, readmission study. Both give the reason No role reaches class RAW.
