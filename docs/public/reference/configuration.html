Configuration reference

Every setting of the platform and its worker: what it means, its unit and its default. 125 settings and 18 ports.

How settings work

Where to write them. In .env, at the root of the repository. Copy .env.example to .env, which lists every setting with its default commented out. .env is never committed, so secrets in it stay on your machine.

Who reads it. Docker Compose passes the whole file to the API. The start script gives the host worker the settings the worker reads, by name, and nothing else from the file: the worker is built not to hold the storage administrator's secret or the master key, so those never reach it. A setting that is not written anywhere uses the default shown on this page.

After a change. The API reads its settings once, when it starts. Run start-dev.ps1 to recreate the API container with the new values. For the worker, run stop-dev.ps1 and then start-dev.ps1. The worker that runs inside the Linux distribution, and the optional quickstart worker, read the environment they are started with and use the defaults shown here.

Names. Every setting starts with MUNITAS_ and is written in upper case with underscores, so none of them can collide with a variable that belongs to another program. Variables that belong to other software, such as the AWS_ ones the storage client library reads, are set by the platform and are not listed.

Secrets. Each one has a development value so that a laptop starts without setup. Those values are published in this repository, so they must be replaced in any shared deployment. Set MUNITAS_ENV=production and the platform refuses to start until the two that matter most have been replaced.

Folders and files on this machine

Where the platform keeps its data, its scratch work and its logs. Most of these hang off one folder, MUNITAS_DATA, so that moving the data folder moves everything with it.

MUNITAS_DATA

The one folder that holds the platform's data on this machine: stored files, the synthetic sample files, downloaded models, scratch work and logs. Use an absolute path with room for several gigabytes of model downloads. Nothing starts without it. Docker Compose and the start script read it from .env, and the start script passes it on to the workers.

Default
None. It is required.
Read by
the worker, Docker Compose

MUNITAS_WORK

The scratch folder a worker uses while it runs a pipeline. By default it is the folder work inside MUNITAS_DATA. It must be an absolute path that is valid on the operating system the worker runs on, and the worker creates it when it is missing.

Default
MUNITAS_DATA/work
Read by
the worker

MUNITAS_CORPUS

The folder of synthetic sample files that practice runs and verification runs read. By default it is the folder synthetic inside MUNITAS_DATA. It is only read, never changed, so it must already exist.

Default
MUNITAS_DATA/synthetic
Read by
the worker

MUNITAS_LOG_DIR

The folder each worker writes its log file into. By default it is the folder logs inside MUNITAS_DATA. A log rolls over at 10 MB and five old files are kept, so logs cannot fill the disk. It must be an absolute path.

Default
MUNITAS_DATA/logs
Read by
the worker

MUNITAS_ALERTS_FILE

The file that alerts are written to: one line of JSON per alert, in one file for every category of alert, each line carrying its category. Inside the API container the path is under /logs, which is the logs folder of MUNITAS_DATA, so by default the file is MUNITAS_DATA/logs/alerts.jsonl on this machine. It rolls over at 10 MB and five old files are kept. An empty value switches the file off, and alerts are then recorded only in the log output and by the part of the platform that raised them.

Default
/logs/alerts.jsonl
Read by
the API, Docker Compose

MUNITAS_KEY_SERVICE_MASTER_FILE

The file that holds the master key of the key service, which keeps each person's key. It is read from a mounted file and never from the environment or the database. The API starts without it, and only the routes that lock a person's data need it. The start script creates the file under infra/secrets.

Default

the API

MUNITAS_API_CA_CERT

A self-signed certificate that the worker trusts in addition to the operating system's own list, for use when MUNITAS_API points at a local HTTPS listener. Only the worker trusts it. Nothing is installed in the operating system's trust store. It is ignored when the file does not exist.

Default

MUNITAS_HOST_WORK_DIR

Only needed for the optional quickstart worker that runs inside Docker Compose (docker compose --profile quickstart up). The absolute path, on this machine, of the folder that worker uses for scratch work. It is not a path inside a container. The folder is created when it is missing. When it is wrong or unset, the quickstart worker refuses to start instead of writing files somewhere that would confuse whatever looks for them later.

Not set.

MUNITAS_STORAGE_VOLUMES_PER_TENANT

How many storage volumes an organisation's bucket is given when it first writes. A volume is a large file that many stored objects are appended into, up to 1 GB, and volumes are never shared between organisations, so this is paid per organisation and not per byte. One is right for many small organisations. An organisation that fills its volume is given another automatically, so a value that is too low costs a brief pause, while a value that is too high can run the machine out of volumes. An organisation expected to be large says so when it is onboarded, and that wins over this setting.

Default
1 volume.

Cloudflare R2 (optional)

R2 is an optional second storage backend. Leave every R2 setting empty on an installation that only uses the built-in storage: a dataset then cannot be sealed against R2, and the refusal says why. The four credential values must come from one and the same R2 API token, created under R2, API, Manage API tokens, with Admin Read and Write permission. Cloudflare shows the token value once, when it is created. The access key id is the token's id, and the secret access key is a SHA-256 hash of its value. Mixing values from two tokens produces a credential that signs storage requests as one identity and Cloudflare requests as another, and that fails in a way that reads like a permissions problem.

MUNITAS_R2_ACCOUNT_ID

The Cloudflare account id.

Default
Not set.
Read by
the API, Docker Compose

MUNITAS_R2_ACCESS_KEY_IDSecret

The id of the R2 API token. It is the access key of the S3 side.

Default
Not set.
Read by
the API, Docker Compose

MUNITAS_R2_SECRET_ACCESS_KEYSecret

The SHA-256 hash of the R2 API token's value, which is the secret of the S3 side. Verification checks that this pair really belongs to the token below, so a mismatched paste is caught by name.

Default
Not set.
Read by
the API, Docker Compose

MUNITAS_R2_API_TOKENSecret

The R2 API token itself. Cloudflare's own REST API (creating a bucket, minting a scoped token, issuing a temporary credential) authenticates with this value as a bearer, while the S3 protocol uses the id and the hash above. The hash is one way, so this value has to be carried separately.

Default
Not set.
Read by
the API, Docker Compose

Writing a version's rows as a table

A caller who names a records file is asking for a table. By default a version is then not sealed without one when the table cannot be written for a reason about the data or a fault in writing it: the seal is refused with the reason, and nothing is left behind. A caller that would rather keep the files without a table says so for one seal. A table that is not written because the platform was told not to, because the files are on R2, or because the file is too large never blocks a seal. The records file comes in one of three shapes, chosen by its name: a JSON list (.json), one JSON row per line (.ndjson or .jsonl) or a Parquet file (.parquet). A JSON list is read whole and takes about six times its size in memory, so its limit is small. The other two are read in batches, so their memory use does not depend on the file, and their limit is on time.

MUNITAS_ICEBERG_PROJECTION

Set it to off to skip writing tables entirely, so that a deployment that has not given the API enough memory for pyarrow can still seal versions as files.

Default
on
Read by
the API, Docker Compose

MUNITAS_ICEBERG_FAIL_CLOSED

By default a version whose caller asked for a table is not sealed when the table cannot be written. Set it to off to seal the files anyway and record the reason.

Default

Read by
the API

Large tables (table jobs)

A table that is large is written by a worker, in a job, and not while a request waits. A seal that names a records file bigger than the inline limit becomes a job. A job is not tied to a request's deadline, so its size limit is far higher than the request limit, and its time limit is the lifetime of its key. The limits a job works within are sent to the worker by the platform, so they are set here and nowhere else.
